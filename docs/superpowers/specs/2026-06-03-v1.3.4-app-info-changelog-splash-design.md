# v1.3.4 App Info, Changelog, and Splash Design

## Scope

Implement only the v1.3.4 supplement requirements:

- REQ-18: make the splash animation feel less linear and more alive.
- REQ-19: add a PickUp information page from the Settings "关于" section.
- REQ-20: show the current version changelog once after install/update.

Mark v1.3.2 and v1.3.3 as completed in the PRD as requested.

## Architecture

Use small, testable modules for version and changelog state. `src/constants/app-info.ts` owns app metadata. `src/constants/changelog.ts` owns user-facing release notes. `src/services/changelog-service.ts` owns AsyncStorage read/write behavior so the one-time modal logic can be tested without rendering the app.

The root layout continues to gate the app with `SplashScreen`. After the splash finishes and providers mount, `ChangelogModal` checks whether the current version was acknowledged and shows itself if needed. Settings links to a new `/about` route and reads the same app metadata constants, removing the stale hard-coded version.

## UI Behavior

The changelog modal uses the existing dark theme and gold accent. It shows a title, short subtitle, version label, a concise list of changes, and a bottom-right "我已知晓" action. Confirming writes the current version to AsyncStorage and suppresses the modal for future launches until the version changes.

The about page is a simple full-screen route with a back button, app identity, slogan, current version, author `Zack Feng`, and email `1179722988@qq.com`. The email row opens `mailto:` when tapped.

The splash screen keeps the same black/gold brand language but replaces the single title fade with staggered card drift, staggered title letters, a small accent pulse, and delayed slogan reveal. It stays within the current startup contract: `onFinish` fires once after the animation window.

## Testing

Run `npx.cmd jest --runInBand` and `npx.cmd tsc --noEmit` after implementation.
